Variables, Naming & CommentsBeginner

A variable is a label pointing to a value in memory — think of it as a sticky note on a box, not the box itself. Python doesn't need a type declaration; the type is inferred automatically from whatever you assign. Naming matters more than it seems: Python has strict rules about what counts as a valid name, and comments (text after a #) let you explain *why* code does something, since the code itself only shows *what* it does.

# price of a train pass in Osaka, in yen
train_pass_price = 3200
station_name = "Ibaraki"
is_available = True

Naming rules

# valid
monthly_rent = 85000
_privateNote = "draft"
fare2024 = 210

# invalid — would raise SyntaxError
# 2024fare = 210        (can't start with a number)
# monthly rent = 85000  (no spaces allowed)
# class = "A"           (class is a reserved keyword)
Solved example Problem: A JR ticket costs 320 yen base fare. Suica card users get a 10 yen discount. Calculate the final fare. 
base_fare = 320

Data Types & Type ConversionBeginner

Every value in Python has a type — a number, a piece of text, a true/false flag — and the type determines what you can do with it (you can add two numbers, but not a number and a raw string). Type conversion is how you deliberately turn one type into another, most often needed when data arrives as text (from a form, a file, or user input) but needs to be treated as a number.

rent = 85000            # int
exchange_rate = 0.0067    # float (JPY → USD)
landlord_name = "Tanaka Fudousan"  # string
first_letter = landlord_name[0]      # indexing
short_name = landlord_name[:6]       # slicing

rent_str = "85000"
rent_int = int(rent_str)            # "85000" → 85000
paid = bool(rent_int)                # any nonzero number → True
Solved example Problem: A form submits salary as the string "280000". Convert it to a number and calculate 20% income tax withheld. 
salary_str = "280000"
salary = int(salary_str)
tax = salary * 0.20

print(f"Tax withheld: ¥{tax:,.0f}")
# Tax withheld: ¥56,000

Numbers & Number SystemsBeginner

Python distinguishes between regular division (which always gives a decimal result), floor division (which rounds down to a whole number), and modulo (which gives you the remainder). Numbers can also be viewed in different bases — binary, hexadecimal, octal — which matters more once you touch lower-level programming, but is good to recognize early.

total_yen = 10000
people = 3

each_pays = total_yen // people      # 3333 (floor division)
leftover = total_yen % people        # 1 yen remainder
exact_share = total_yen / people     # 3333.333...

round(exact_share, 2)              # 3333.33
bin(10), hex(255), oct(8)     # binary/hex/octal representations
Solved example Problem: Three friends split a 10,000 yen izakaya bill. Find each person's floor-divided share and the leftover yen. 
total_yen = 10000
people = 3

each_pays = total_yen // people
leftover = total_yen % people

print(f"Each pays ¥{each_pays}, leftover ¥{leftover}")
# Each pays ¥3333, leftover ¥1

Boolean Logic & NoneBeginner

Booleans are just True/False, but Python also treats certain values as "truthy" or "falsy" in a condition — an empty list, an empty string, or the number 0 all behave like False without you writing it explicitly. None is a special value meaning "no value yet" — different from 0, an empty string, or False — and it needs its own comparison style (is None, not == None).

cart_items = []
if not cart_items:              # empty list is falsy
    print("Cart is empty")

discount_code = None
final_price = 1000 - (discount_code or 0)   # short-circuit: None → 0

tracking_number = None
if tracking_number is None:
    print("Package not shipped yet")
Solved example Problem: A checkout has no discount code entered (None). Calculate the final price of a 1000 yen item, falling back to 0 discount safely. 
price = 1000
discount_code = None

final_price = price - (discount_code or 0)
print(f"Final price: ¥{final_price}")
# Final price: ¥1000

Constants, Chained Assignment & SwappingBeginner

Python has no true "constant" keyword — instead, writing a variable name in ALL_CAPS is a convention that tells anyone reading the code "don't reassign this." Chained assignment lets you set several variable names to the same value in one line, and Python's tuple-style swapping lets you exchange two variables' values without a temporary holder, unlike most other languages.

MAX_STUDENTS_PER_BATCH = 20     # UPPER_CASE by convention = constant
EARLY_BIRD_DISCOUNT = 0.15

base_fare = child_fare = senior_fare = 150   # chained assignment

adult_fare, student_fare = 300, 210
adult_fare, student_fare = student_fare, adult_fare   # swap in one line
Solved example Problem: A fare table accidentally has weekday_fare = 210 and weekend_fare = 260 swapped. Fix it in one line. 
weekday_fare = 210
weekend_fare = 260

weekday_fare, weekend_fare = weekend_fare, weekday_fare
print(weekday_fare, weekend_fare)
# 260 210

OperatorsBeginner

Operators are the symbols that combine or compare values: arithmetic (+ - * / // %), comparison (== != > <), and logical (and or not). Python adds a few convenient extras beyond the basics — the ternary expression for one-line if/else, the walrus operator for assigning inside a condition, and chained comparisons that read like plain math (0 < x < 10).

total = (3200 + 1200) * 1.1   # fare + baggage fee, with 10% tax
is_expensive = total > 5000
can_afford = (budget >= total) and is_expensive == False

accepted_cards = ["Suica", "ICOCA", "PASMO"]
"ICOCA" in accepted_cards   # True — membership

status = "discount" if age < 12 else "full fare"   # ternary

if (balance := 10000 - fare) > 0:   # walrus operator
    print("Remaining balance:", balance)

if 100 <= fare <= 500:              # chained comparison
    print("short-distance fare")
Solved example Problem: A fare gate needs to check if a rider's IC balance (currently ¥300) is enough to cover a ¥210 fare, and confirm the fare is a valid "short-distance" fare (100–500 yen). 
balance = 300
fare = 210

Strings & Escape SequencesBeginner

Strings come with a large built-in toolkit for cleaning, splitting, joining, and reformatting text — essential since real-world data is rarely already in the shape you need. Escape sequences (\n, \t, \\) let you embed special characters like new lines or tabs inside a string, while a raw string (prefixed with r) tells Python to ignore escape sequences entirely, useful for file paths.

address = "  Ibaraki-shi, Osaka  "
clean = address.strip()
parts = clean.split(",")
joined = " / ".join(parts)
upper = clean.upper()

name = "Refadul"
f_string = f"Hello, {name}"            # preferred in modern Python

receipt = "Item\tPrice\nBento\t¥480\nTea\t¥150"   # \t and \n escapes
literal_backslash = "C:\\Users\\Refadul"          # escaped backslash
windows_path = r"C:\Users\Refadul\Documents"       # raw string — no escaping needed

"Osaka" in address       # substring check — True
Solved example Problem: A scraped utility bill reads " Electricity: ¥8,400 ". Clean it up and extract just the numeric amount as an integer.

Input & OutputBeginner

input() pauses a program and waits for the user to type something — and always hands it back as a string, even if it looks like a number, so it usually needs converting. print() does more than just display text: its sep and end options control spacing, and f-strings let you format numbers (like adding comma separators to a yen amount) directly inside the printed text.

name = input("Enter your name: ")
budget = int(input("Monthly budget (yen): "))

print("Hello", name, sep=", ", end="!\n")
print(f"Budget: ¥{budget:,}")   # f-string with thousands separator

# (if income = 250000) → Recommended max rent: ¥75,000

Control FlowBeginner

Control flow is how a program decides what to run, and how many times. A while loop repeats as long as a condition stays true (good when you don't know the number of repetitions in advance), a for loop repeats a fixed number of times or over a known collection, and break/continue give you early exits or skips inside either. Loops can also be nested — one loop running fully inside each pass of another — for anything with two dimensions, like a table. range() is the standard way to loop a fixed number of times without a real list, and for...else (like while...else) runs its else block only if the loop finished normally, without hitting a break.

balance = 1500
fare = 210

while balance >= fare:
    balance -= fare
    print("Ride taken, balance:", balance)
else:
    print("Balance too low, please recharge.")

for station in ["Ibaraki", "Takatsuki", "Shin-Osaka"]:
    if station == "Takatsuki":
        continue
    print("Stopping at", station)

# range() — loop a fixed number of times without a real list
for i in range(5):
    print(f"Ticket #{i + 1} issued")

# for...else — else runs only if the loop never hit break
tickets = ["A1", "A2", "A3"]
for ticket in tickets:
    if ticket == "B1":
        print("Found B1!")
        break
else:
    print("B1 was never found")

# nested loop — every station × every ticket type
stations = ["Ibaraki", "Takatsuki"]
ticket_types = ["Adult", "Child"]
for station in stations:
    for ticket in ticket_types:
        print(f"{station} — {ticket} fare")
Solved example Problem: A vending machine needs at least 150 yen. Simulate inserting 100 yen coins one at a time until there's enough, then print the change owed.

Data StructuresBeginner

Python's four core built-in collections each fit a different shape of data. Use a list when order matters and the contents can change; a tuple when order matters but the contents are fixed once created; a dictionary when each value needs a meaningful label (a key) rather than just a position; and a set when you only care about unique items and don't need any particular order.

# List — ordered, changeable
monthly_expenses = [85000, 12000, 8000]

# Tuple — ordered, unchangeable
apartment_location = ("Ibaraki", "Osaka", "Japan")

# Dictionary — key/value pairs
lease = {"rent": 85000, "deposit": 170000, "key_money": 85000}

# Set — unordered, no duplicates
visited_stations = {"Ibaraki", "Osaka", "Kyoto", "Osaka"}  # duplicate dropped
Solved example Problem: Given a lease dictionary with rent, deposit, and key money, calculate the total move-in cost.

total_move_in = sum(lease.values())
print(f"Total move-in cost: ¥{total_move_in:,}")
# Total move-in cost: ¥340,000

Data Structure MethodsBeginner

Each collection type comes with its own built-in methods for adding, removing, or combining data — knowing the right method saves you from writing manual loops for things Python already handles. Lists focus on order-based operations (add/remove/insert at a position), dictionaries focus on safe key-based lookups, and sets focus on comparing groups of unique items against each other.

List methods

expenses = [85000, 12000]
expenses.append(8000)
expenses.insert(0, 170000)
expenses.remove(12000)
last = expenses.pop()
expenses.extend([5000, 3000])

expenses.sort()                 # sorts the list in place, ascending
expenses.reverse()               # reverses the list in place
expenses.count(85000)          # how many times a value appears
expenses.index(170000)          # position of the first match
backup = expenses.copy()         # a separate copy, not the same list
expenses.clear()                 # empties the list entirely

Dict methods

lease = {"rent": 85000, "deposit": 170000}
lease.get("key_money", 0)   # safe lookup, default 0 if missing
lease.keys(), lease.values(), lease.items()
lease.update({"agency_fee": 85000})

lease.pop("deposit")              # removes a key and returns its value
lease.setdefault("key_money", 0)  # adds the key only if missing
lease.clear()                    # empties the dict entirely

Set methods

tokyo_pass = {"Shibuya", "Shinjuku"}
osaka_pass = {"Umeda", "Shinjuku"}
tokyo_pass.union(osaka_pass)
tokyo_pass.intersection(osaka_pass)             # {"Shinjuku"}
tokyo_pass.difference(osaka_pass)               # {"Shibuya"}
tokyo_pass.symmetric_difference(osaka_pass)     # {"Shibuya", "Umeda"}

tokyo_pass.add("Ikebukuro")             # adds one item
tokyo_pass.remove("Shibuya")          # removes an item — errors if missing
tokyo_pass.discard("Ginza")           # removes if present, no error if missing
tokyo_pass.clear()                    # empties the set entirely

Tuple methods

Tuples are immutable, so they only have two methods — nothing that could change their contents.

fare_history = (210, 210, 380, 210)
fare_history.count(210)     # 3 — how many times 210 appears
fare_history.index(380)     # 2 — position of the first 380
Solved example Problem: Two commuter passes cover overlapping stations. Find which stations are shared, and which are exclusive to each pass.

shared = tokyo_pass.intersection(osaka_pass)

Nested Data StructuresIntermediate

Real-world data is rarely flat — a list of records is usually a list of dictionaries (each dictionary being one record with named fields), and grouped data is often a dictionary where each value is itself a list. A third common shape is the 2D list (a list of lists) — used for anything grid-like, such as a seating chart or a fare table between stations, where you need two coordinates (row and column) to find a value. Learning to read and update these nested shapes (accessing a value two or three levels deep) is what makes working with realistic data manageable.

students = [
    {"name": "Refadul", "course": "AWS Cloud Practitioner", "fee": 28000},
    {"name": "Nabila", "course": "Software Mentorship", "fee": 45000},
]
for student in students:
    print(student["name"], "→", student["course"])

expenses_by_category = {
    "housing": [85000, 170000],
    "food": [12000, 8000, 5000],
}
expenses_by_category["food"].append(3000)

# 2D list — a fare matrix between 3 stations (row = from, column = to)
fare_matrix = [
    [0,   150, 210],   # from Station A
    [150, 0,   180],   # from Station B
    [210, 180, 0],     # from Station C
]
fare_a_to_c = fare_matrix[0][2]   # row 0 (Station A), column 2 (Station C) → 210

for row in fare_matrix:
    for fare in row:
        print(fare, end="  ")
    print()
Solved example Problem: Given the students list above, print only students whose course fee is over 30,000 yen. 
for student in students:

MutabilityIntermediate

Some Python types can be changed after creation (lists, dictionaries, sets — these are mutable), while others cannot (numbers, strings, tuples — these are immutable). This matters more than it first appears: if you pass a mutable object into a function and change it there, the original outside the function changes too, since both point to the same underlying data.

expenses = [85000, 12000]
expenses.append(8000)      # list is mutable — changed in place

lease_terms = ("12 months", "no pets")
# lease_terms[0] = "6 months"  → TypeError, tuples are immutable
Solved example Problem: A function adds a late fee to a list of expenses. Show that the change is visible outside the function, because lists are mutable.

    expense_list.append(2000)

add_late_fee(expenses)

print(expenses)
# [85000, 12000, 2000] — original list changed
Practice
  1. Explain why passing a list into a function and modifying it there also changes the original list, while passing a string does not.
    Show answer
    # A list passed into a function is the SAME object in memory —
# changing it inside the function changes the original.
# A string can't be changed in place at all (immutable), so
# reassigning it inside a function only affects the local copy.

Slicing & RepetitionIntermediate

Slicing lets you pull out a sub-section of a list or string using [start:stop:step] notation, without writing a loop — a negative step reverses the sequence, and negative indexes count from the end. fares = [150, 210, 280, 380, 470]

fares[::-1]       # reversed
fares[-2:]        # last two fares

fares[1:3] = [999, 888]   # slice assignment — replace a chunk in place

empty_month = [0] * 12     # 12 months of zero rent, as a template
divider = "-" * 30         # a 30-character receipt divider line

ComprehensionsIntermediate

A comprehension builds a new list, dictionary, or set in a single, readable line instead of writing a full loop with an empty container and repeated .append() calls. There are two distinct patterns worth telling apart: filtering (an if at the end drops some items entirely) versus transforming every item (an if...else in the middle changes each item's value but keeps all of them).

prices = [480, 980, 1500, 320]

with_tax = [p * 1.1 for p in prices]
affordable = [p for p in prices if p < 1000]           # filter
labels = ["expensive" if p > 1000 else "cheap" for p in prices]  # transform

items = ["bento", "onigiri", "tea"]
price_map = {item: price for item, price in zip(items, prices)}   # dict comprehension
unique_price_tiers = {p // 500 for p in prices}                # set comprehension
Solved example Problem: Given a list of exam scores, label each one "pass" or "fail" using a 60-point threshold, in one line. 
scores = [45, 72, 60, 88, 33]

results = ["pass" if s >= 60 else "fail" for s in scores]
print(results)
# ['fail', 'pass', 'pass', 'pass', 'fail']

Functional Tools & LambdaIntermediate

A lambda is a small, unnamed function written in a single line — useful when you need a quick, throwaway piece of logic without the ceremony of a full def block, especially as an argument to another function. map() applies a function to every item in a collection, filter() keeps only the items that pass a test, and all()/any() check whether a condition holds for every item or just one, respectively.

prices = [480, 980, 1500, 320]

add_tax = lambda price: price * 1.1
add_tax(480)   # 528.0

with_tax = list(map(add_tax, prices))
cheap_items = list(filter(lambda p: p < 1000, prices))

all(p > 0 for p in prices)     # True — every price is positive
any(p > 1000 for p in prices)  # True — at least one over 1000 yen
Solved example Problem: Check whether a list of exam scores contains at least one failing grade below 60. 
scores = [72, 88, 55, 91]

print(f"Has a failing grade: {has_failure}")
# Has a failing grade: True

Scope, Namespaces & Nested FunctionsIntermediate

Scope is about where a variable "lives" and where it can be seen from. Variables created inside a function are local to it and disappear once the function finishes; variables created outside any function are global and visible everywhere. Trying to modify a global variable from inside a function requires the global keyword, and a function nested inside another function needs nonlocal to modify a variable from its enclosing (but not fully global) scope.

exchange_rate = 0.0067   # global
conversions_done = 0

def convert_to_usd(yen):
    global conversions_done
    conversions_done += 1
    return yen * exchange_rate

def rent_tracker():
    total = 0
    def add_payment(amount):
        nonlocal total
        total += amount
        return total
    return add_payment

track = rent_tracker()
track(85000)   # 85000
track(85000)   # 170000 — total remembered between calls
Solved example Problem: Build a rent tracker that remembers a running total across multiple payments, using a nested function.

Docstrings & Type HintsBeginner

A docstring is a string placed right after a function's definition line that explains what the function does, what it expects, and what it returns — different from a regular comment because tools like help() can read and display it. Type hints are a lighter-weight companion: optional annotations on the parameters and return value (def f(x: int) -> float:) that document intent without Python actually enforcing them. Both exist for the same reason — helping the next reader (often future-you) understand a function without reading its full body.

def calculate_total_rent(monthly_rent: int, months: int) -> int:
    """
    Calculate total rent paid over a lease period.

    Args:
        monthly_rent (int): Rent in yen per month.
        months (int): Number of months on the lease.

    Returns:
        int: Total rent paid in yen.
    """
    return monthly_rent * months

Debugging & assertIntermediate

Debugging is the skill of figuring out why code isn't doing what you expect. A quick print() of a variable's value or type is often the fastest way to check an assumption, and Python's error messages (tracebacks) point you to the exact line and type of problem if you read them carefully. An assert statement is a lightweight sanity check — it stops the program immediately with a clear message if a condition you expect to be true turns out to be false.

rent = 85000
utilities = "12000"   # bug: this should be an int, not a string

# total = rent + utilities
# TypeError: unsupported operand type(s) for +: 'int' and 'str'

assert rent > 0, "Rent must be positive"
assert rent <= 300000, "Rent exceeds budget"

Useful Built-in HelpersBeginner

stations = ["A", "B", "C", "D"]
for station, fare in zip(stations, fares):
    print(station, fare)
